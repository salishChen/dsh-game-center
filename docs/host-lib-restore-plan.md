## 1. 差异来源说明（回应 PM：为何 `EB824B19…` 读数不同）

此前我报告"Git 基线里 `lib/index.js` 是 `EB824B19…`"，该读数**错误**，原因在我的测量方法：

| 做法 | 结果 |
| --- | --- |
| `git cat-file -p <sha>:<path>` 再用 PowerShell `>` 重定向写文件 | 4819 字节 → 变成 **6932 字节**，SHA-256 = `EB824B19…`（错误） |
| `git show <sha>:<path> > file`（cmd 重定向，原样字节） | 4819 字节，SHA-256 = `93F30A7B…`（正确，与批准值一致） |

PowerShell 的 `>` 会按自身编码规则重写文本流（编解码/换行处理），**不是字节复制**。因此凡是用 PS 重定向把 git 对象落盘再算哈希的做法都会失真。这条已作为方法教训记录，后续所有字节级对账一律用 `git show ... > file`（cmd）或 `git cat-file` 直出二进制。

**结论更正**：`3b0fb96` 的 `lib/` 就是已批准部署产物的字节级副本（21/21 MATCH）。

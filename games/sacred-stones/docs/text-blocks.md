# 文本块筛选（第一轮 witness）

目标：从 4,450 个已解码 LZ77 块里找出"文本"块，为字库下界提供依据。
输入：`extract/lz77-pointers-4454.tsv`（scope=dlen>=32，4,450 行）。
脚本：`tools/text-blocks.py`（提交 820c741 前后）。

## 判据 v1（PM 初版）与结果

判据：解压流里同时出现 `0x0A` 与 `0x0B` 两个控制码。

| 指标 | 数值 |
| --- | --- |
| 候选块（dlen>=32） | 4,450 |
| 成功解码 | 4,450 |
| 含 0x0A 或 0x0B | 1,795 |
| 同时含 0x0A 与 0x0B | 1,382 |

**结论：判据 v1 不可用。** 0x0A/0x0B 在图形数据里同样常见，1,382 块里绝大多数是图块。

## 判据 v2（收紧）与结果

判据：同时含 0x0A/0x0B，最大字节 ≤ 0x40，不同字节数 ≤ 48。

| 指标 | 数值 |
| --- | --- |
| 命中 | 106 |
| 抽样头部 | `1000100010001000…`、`1500150015…`、`2b002b002b00…` |

**结论：判据 v2 也不可用。** 头部是重复的 16 位图样（每 2 字节一个值、重复 600 次），
是 tile/调色板数据，不是文本。

## 分布（为什么字节级判据分不开）

`max_byte >> 4` 直方图（4,450 块）：`0x0-0x3` 共 32+101+91+103 块，`0x6` 363 块，
`0xF` 段 2,502 块。图形占绝大多数且字节分布覆盖全 0–255，文本夹在中间无法靠字节范围切开。

## 下一步（不是继续调阈值）

1. 找 **文本指针表**：FE8 的文本由 msg 指针表 + 字库索引组成，先定位表而不是在 LZ77 流里猜；
   判据：连续 4 字节指针均落在 ROM、目标处出现 `0x00` 结尾的字节序列。
2. 用**已确认的字符串**（标题画面"圣魔之光石"、菜单"开始游戏"）反查，交叉验证表结构。
3. 字库下界：等文本表找到后，统计索引最大值，给出字库上界候选。

## 诚实边界

- 本轮只证明了"LZ77 流内没有用字节范围可分离的文本"；
- 不代表 ROM 没有文本，文本可能在未压缩区或自定义结构中；
- `0x0A/0x0B` 作为控制码的假设本身未经游戏内验证。

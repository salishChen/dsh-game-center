# 盲区（black-on-black）取样法：三种做法，三个不同的数

盲区的定义是「**硬件的输出对混合开关不敏感**的像素 ∩ BG1 不透明」。问题在于"开关"怎么切。
下面三个数是同一个帧 900、同一个 savestate，只有"怎么切 BLDCNT"不同。

| 取法 | blind 像素 | 说明 |
| --- | --- | --- |
| A：跑帧**前**写一次（写 0） | **1,250** | 写进去的 0 一直生效到帧末游戏重写 ⇒ 等于"整帧关混合"，是比较强的对照 |
| B：第 0 行渲染前写一次（半帧） | **12,574** | 游戏在同一帧里马上改回 ⇒ 两次跑出来的画面**逐字节相同** ⇒ 盲区退化成整个 BG1 掩码，**这个实验没有对照** |
| C：每条扫描线渲染前强制写（现行） | **931** | 整帧处在被指定配置下；这才是"混合开关"的有效对照 |

另有 `A ⊃ C` 的实测关系：**A = 1,250，C = 931，`onlyC`（C 有 A 没有）= 0**，即 C 是 A 的子集；A 多出的 319 个像素是"关掉混合看不出来、但改变目标层看得出来"的那批。

## 由此得到的规则

1. **报盲区数必须同时报取法**，否则 931 / 1,250 / 12,574 三个数都"有出处"却互不可比。
2. 取法 B 要特别警惕：它**不报错**，还给出一个自洽的大数（正好等于掩码），看起来像"发现整层都是盲区"。
3. 判据要能自证"对照真的发生了"：C 的脚本在两次取样读回同一个 `BLDCNT` 时直接 `refused` 退出码 3，就是为了防 B 这种情况被当成结果。
4. **曾经记录为 931 的那一轮，其取法未能复现**（见下），因此那个 931 的来历目前只能归到"取法 C 的某一版"，不构成独立证据。

## 未能复现的那一轮（诚实记录）

- 曾在"改成逐行强制写之前"的一轮里得到 931，当时自述为"半帧对照"。
- 事后用 B 复现，得到的是 12,574（实验无对照）；用 A 复现，得到 1,250。
- 结论：**931 不能由 A 或 B 复现**。所以"半帧版也给 931，是蒙对"这个说法应改成更保守的表述：
  **那一轮的取样细节已无法复原，931 只能以取法 C 为准**，它目前只有"取法 C 一次实现"这一条证据链。
- 目前盲区真正的交叉验证只剩两条：取法 C 的实现 + 逆向的静态渲染器；硬件自身对撞那条只有在取法 C 下才算数。
